# 空间效率评估 rubric

> 本 plugin 的第二招牌能力。`evaluate_efficiency` 工具按本 rubric 计算指标；本文件解释每项指标的含义、目标区间与改进方向。
> 效率评估是**只读**的——它诊断，不修改 `modules.json`。改进需走 design / edit 链路。

## 两层评价

```
Layer 1  工程合规  "有没有错？"   由 validate_layout 保证（越界/重叠/挡门）
Layer 2  空间效率  "够不够省？"   本 rubric 五项指标
```

Layer 1 不通过谈不上效率。效率评估假设 modules.json 已通过 validate_layout（故占地面积可按互不重叠精确求和）。

## 五项指标

### 1. 家具密度 furnishingDensity = 占地面积 / 设计区面积

- **目标区间 30%–65%**。
- 偏低（<30%）：空间空旷，没充分利用——可加储物、加功能。
- 偏高（>65%）：拥挤，动线/留白被挤压——考虑换更小/可折叠/多用途件。
- 小空间健康值通常在 45%–60%：塞得下功能又留得出动线。

### 2. 动线/留白占比 circulationRatio = 1 − 家具密度

- **目标区间 35%–70%**。
- 这是「可走动 + 有意识留白」的自由地面。注意：高 circulationRatio 不等于动线好——它只衡量量，不衡量动线是否连贯（连贯性靠截图复核主通道≥800mm 是否贯通）。

### 3. 多用途占比 multipurposeRatio = 多用途模块数 / 模块总数

- **目标 ≥30%**，越高越好（小空间核心杠杆）。
- 配套指标 **复用红利 reuseBonus** = 多用途件多承担的功能数之和（一件墨菲床同时算睡+休闲，红利+1）。
- 偏低：说明在用一堆单功能件硬塞——优先替换为墨菲床/沙发床/餐工两用桌/吧台等。

### 4. 储物占地占比 storageAreaRatio = 储物模块占地 / 设计区面积

- **目标区间 8%–30%**。
- 偏低：收纳不足，住进去会乱——加到顶柜/壁挂搁板（壁挂不占地，靠数量补）。
- 注意壁挂件占地小，storageAreaRatio 低不一定代表收纳差，要结合 storageModuleCount 与竖向利用判断。

### 5. 功能覆盖率 functionCoverage = 已覆盖功能 / 期望功能

- 仅当调用方传入 `requestedFunctions` 时计算。
- <100% 时报告列出**缺失功能**——这些是软分区取舍阶段被砍或被复用吸收的功能，需向用户确认是否可接受。

## 解读原则

1. **指标是诊断不是判决**：目标区间是常见健康值，不是硬阈值。异形户型、特殊需求可合理偏离，但要能说出 WHY。
2. **组合看，别单看**：高密度 + 低多用途 = 用单功能件硬塞（差）；中密度 + 高多用途 + 功能全覆盖 = 小空间打包的理想态（好）。
3. **效率服务于体验**：省出来的地面要变成有意识的留白/动线，不是碎成 <600mm 死角。截图复核窄缝。

## 改进方向速查

| 症状 | 改进 |
|------|------|
| 密度偏高、动线不足 | 换可折叠/多用途件；移除可选件（边几/单椅）|
| 多用途占比低 | 床→墨菲床/沙发床；餐桌→餐工两用桌；加吧台兼隔断 |
| 储物不足 | 加到顶柜（吃满实墙）+ 壁挂搁板（竖向）|
| 功能覆盖不全 | 回软分区，用复用/共享关系把缺失功能塞回去 |
| 密度偏低、空旷 | 补储物/功能；或确认是否刻意留白 |
