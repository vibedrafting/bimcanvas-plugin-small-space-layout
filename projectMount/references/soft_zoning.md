# 功能软分区模型

> 软分区是本 plugin 的第一招牌能力。它解决「开放主间里睡/工作/烹饪/休闲怎么共存」的核心矛盾。
> 软分区记录在 `design_plan` 的 `soft-zoning` 标签里（`save_design_plan`），**不是** `zones.json` 里的几何子 zone。

## 一、什么是软分区

**硬分区**（interior-layout 的世界）：用墙把空间切成独立房间，每个房间一个功能。
**软分区**（小空间的世界）：开放主间不切墙，用**家具群组 / 地毯 / 视线方向 / 动线 / 标高 / 软隔断**把一块连续空间划成若干功能区。功能区之间边界是模糊的、可重叠的、可随时间转换的。

> **核心论点**：软分区不是把开放间假装成几个小房间，而是承认功能会**叠加**和**复用**，并把这种叠加关系设计成有意图的，而不是家具乱放后的偶然结果。

## 二、软区的三种邻接关系

| 关系 | 含义 | 例子 |
|------|------|------|
| **并置**（adjacent） | 两功能区在空间上相邻、各占一块地面 | 工作区在窗边，睡眠区在内侧 |
| **复用**（time-share） | 同一块地面在不同时段是不同功能 | 墨菲床区：白天=休闲，夜间=睡眠 |
| **共享**（shared） | 一件家具同时服务两个功能区 | 餐桌兼工作台，吧台兼餐区兼隔断 |

**【必须】**软分区方案里每个功能区必须显式标注它与相邻区的关系是并置 / 复用 / 共享，并说明 WHY。这是软分区区别于"随便摆家具"的关键。

## 三、怎么切软区（无墙划分手法）

1. **采光轴定主区**：最好的采光面（窗墙）留给使用频率最高、最需要光的功能（工作 / 休闲），不要被高柜或床堵死。
2. **入口定过渡区**：进门第一块地面是过渡区（玄关 / 收纳），不直接是私密的睡眠区——隐私梯度从入口向深处递进。
3. **卫生间墙定服务带**：卫生间外墙这一侧通常排厨房 / 储物 / 设备（管线集中），形成"服务带"。
4. **家具背靠做软隔断**：用沙发背、矮柜背、开放书架背朝向来暗示区界，而不是砌墙。
5. **动线穿缝不穿区**：主通道从功能区之间的缝穿过，不要从某个功能区正中穿过（破坏该区完整性）。

## 四、软分区方案要素（save_design_plan soft-zoning 的内容结构）

软分区方案（markdown）建议包含：

```
## 开放主间画像
（从 get_open_space 读到的：采光面 / 入口墙 / 卫生间侧 / 最长可用实墙 / 总面积）

## 功能清单与取舍
（用户要哪些功能？空间放得下吗？放不下时保留哪些、哪些走复用/共享？—— 战略选择点，必要时 AskUserQuestion）

## 软区划分
对每个功能区：
- 区名（睡眠区 / 工作区 / 烹饪区 / 休闲区 / 过渡区…）
- 大致位置（靠哪面墙 / 哪个角 / 占地大概范围）
- 锚点家具（这个区靠什么大件定位）
- 与相邻区的关系（并置 / 复用 / 共享 + WHY）

## 设计目标
（参考 space_efficiency.md 的品质维度，声明本方案追求什么：动线 / 复用率 / 采光 …）
```

**【必须】**软分区只定"哪块地是什么功能、家具大概在哪、怎么复用"，**不定**精确坐标——坐标是 packing-brief 和 placement 阶段的事。
**【必须】**软分区阶段不写 `modules.json`。

## 五、常见错误

| 错误 | 正确做法 | WHY |
|------|---------|-----|
| 把开放间切成假房间 | 用家具/视线做软隔断 | 砌墙思维丢掉开放空间的通透与复用 |
| 床堵在窗前 | 采光面给活动区，床退到内侧 | 床堵窗既遮光又浪费最好的采光资源 |
| 睡眠区紧挨入口 | 隐私从入口向深处递进 | 进门即见床，无过渡，体验差 |
| 功能区各自为政、不声明复用 | 显式标注复用/共享关系 | 不复用就放不下，复用不声明就会被 placement 当成冲突 |
| 主通道穿过功能区正中 | 通道走区与区之间的缝 | 穿区破坏功能完整性 |
